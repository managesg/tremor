## 1. Hypothesis

In our median session the cache-read share of USD is below 67%. Exploratory (owner
2026-11-19).

## 2. Concept and status

Agent cost is shaped by the cache (Diogo Almeida's talk). The 67% is read from a slide,
unconfirmed and drawn at an older price (SCIENCE 1.5, note 9). Status: speculative (talk claim).

## 7. Primary metric (one)

Cache-read share of cost per session: USD of cache-read tokens / total USD of the session, as a
fraction, at a price sheet read and recorded at run time, per model. Reported as the median
across sessions. If the price sheet cannot be read, USD is null and the prediction is not
tested (WORKPLAN wave 2, 2.2).

## 8. Secondary metrics (exploratory)

Per session, main and subagent separately:
- Tokens by class (tokens): input, cache-write, cache-read, output.
- Cost share by class (USD of class / total USD).
- Cache hit rate: cache-read / all input-side tokens, both counts shown.
- Cold start: cache-write tokens in a subagent's first call (tokens).
- Tool-call reads per write: (Read, Grep, Glob calls) / (Edit, Write calls). Compared with the
  ratio near 11 from the talk, as the single-agent null for H9. The talk's 11.4 counts database
  reads per write (SCIENCE 1.5, note 1). Ours counts tool calls by name, so it is a proxy, not
  the same quantity.

## 9. Minimum effect of interest

None is set by PLAN beyond the threshold itself: the prediction is refuted if the median is 67%
or more. No margin is invented here.

## 10. Sample size and stopping rule

- n = 42 sessions with usage fields: 37 subagent, 5 main (pre-freeze run).
- PLAN's stop rule: fewer than 30 sessions with usage fields means counts only, no claim. 42
  clears that floor, but the primary analysis stays **exploratory**, not confirmatory, for
  three reasons:
  1. the owner's decision (2026-11-19);
  2. the main-session stratum has only 5 sessions;
  3. the token shares of this corpus were seen before the freeze.
- The main-session figures (n = 5) are reported as counts and ranges only, with no interval
  and no claim (design choice: 5 is far below the 30-session floor PLAN sets for a claim).
- n is fixed at freeze. If the re-check at freeze finds fewer than 30, counts only.
- Sessions added later are a new run under a new freeze, not an extension of this one.

## 11. Analysis

- Median cache-read USD share with a 95% percentile interval, cluster bootstrap by session
  (PLAN: "bootstrap by session"); 10,000 resamples (SCIENCE 5).
- Refuted if the median is 67% or more. An interval that contains 67% is reported as
  inconclusive (design choice, following the SCIENCE 5 rule that a point estimate alone is
  not a result).
- Correction: none. E8.1 is outside every Holm family; Holm does not apply. The output
  carries the label "exploratory".
- Subagent and main sessions are never pooled without also showing the split, because 37 of
  the 42 are subagent sessions and the pooled median is mostly a subagent figure.
- With no price sheet recorded, the primary is reported as "not computed (USD null)". Token
  shares are reported as token shares.

## 12. Kill criteria

- The median cache-read share of USD is 67% or more: the exploratory prediction does not
  hold on this corpus, and we stop assuming our sessions are cheaper in cache reads than the
  slide's figure. This is not a confirmatory refutation.
- Usage fields absent or unusable at freeze: the transcript part is dropped; only new runner
  episodes are measured (every runner episode logs the four classes).
- Fewer than 30 sessions with usage fields: counts only, no claim.

## 13. Sanity checks before the run

- A canary string placed in a message never reaches the output (W1-05 test).
- Token accounting balances: per session, the four classes sum to the total used for shares.
- The probe prints key names and counts only.
- Price sheet URL and date recorded in the manifest.

## 14. Known threats to validity

- One user's sessions, 42 of them, mostly subagent sessions (37).
- Token shares were seen before the freeze (see "Pre-freeze observation").
- Prices change; the slide was drawn at an older price, so the comparison with 67% is loose.
- Old transcripts may record usage differently across client versions; whether they can serve
  as a cost record at all is itself one of the three questions E8.1 answers.
- Reads per write counts tool calls by name; it does not see reads done through Bash.

## 16. Decisions it feeds, and what would change our mind

- Cold-start term in the run gate: a large first-call cache write raises the minimum task size
  worth sending to a worker.
- H9's null: if one agent alone shows about 11 reads per write, that ratio is not a team
  signature.
- Cost record: if the fields are inconsistent, old transcripts are not used as a cost record.
- A median at or above 67% would make us accept the slide's figure for our own sessions. More
  sessions, well above the floor, would be needed before any of this is stated as a finding.
