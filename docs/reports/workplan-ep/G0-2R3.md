Two processes cannot interleave a check and its write: `settle`, `stop_batch` and `reserve` each read and write under
one flock, and every reserve re-checks the gate.

Limits, none of them a stop bypass:
- A stop hidden in a non-`.jsonl` file of a **non-pinned** directory is invisible to the other ledgers. This is the
  documented per-directory shortcut, and the real host is pinned.
- At the spend level, `ep1.settle` is still accepted with no canary, with an inconclusive canary or with a crashed canary
  that left no stop, and ar1 then opens. This is N2/N3; only the driver's `_check_open` blocks it.
