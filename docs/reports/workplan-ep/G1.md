## Verdict

**Rung 0: ACCEPT-WITH-NOTES. The EP-1 pre-registration may be drafted, but it may NOT be frozen.**

The instrument is sound for:
- EP-1's primary `Y` (`distinct_passing / slots`);
- the exact tables for C, D, S, L and H.

It is not sound for two read-offs that `prereg/EP1.md` section 8 cites:
- the claim-collision rate;
- the false-done rate.

Separately, the refusal stop rule creates a one-sided bias in the code arm (D3). The model loop (B2) is a new layer
that no gate has tested yet.

## 3. Pairing and independence

Holds:
- **Same task set and board seed across arms.** Within a set, `seed = s` and `_taskset(pid, s)` are the same in every
  arm. Common random numbers are exact: the edge checks `play(q=0) == none` and `play(q=1) == code` compare per set,
  and they pass.
- **Cluster bootstrap by task set.** `stats.hdi(data, "set")` resamples by set.

Does not hold, or is not checked:
- **Seeds are not independent across q.** Every q reuses seeds `seed + k`, so the adopter sets are nested across q.
  - Adoption draws do not depend on the practice either: the key `adopt:{seed}:{agent}`.
  - So the seven q = 1/2 practice cells are one adoption sample, not seven independent ones.
  - This is harmless for the per-q expectations. It must not be read as replication. EP-1 has no q, so it does not
    carry over.
- **Pairing is not verified** (M12, M13, M14).
  - Records carry `seed`, but no task-set hash.
  - No check covers the bootstrap CI. Under common random numbers the endpoint CIs must collapse to [1, 1] and
    [0, 0].
- **The `both` arm is run but never compared.** It has 0 expectations. For A, `both` equals `code` by construction.
- **Rung 0 uses the `train` split;** `prereg/EP1.md` uses `heldout`. This is minor: `Y` does not depend on task
  content.

## 5. Coverage of EP-1: what rung 0 does not exercise

**D1. The claim-collision read-off is not comparable across arms (blocks the freeze).**
- Under enforcement, a refused duplicate claim never reaches the board. So `orders.compute` reports 0 for `code` and
  `both` in every episode.
- v2 expects 142837/907200 for `code`. The cell passes only because its tolerance (0.207) is larger than its value.
- With models, `none`/`play` against `code`/`both` would compare attempted collisions against admitted collisions.
- Fix: define the rate from attempts (board claims plus refused claims), or report refusals beside it. Then tighten
  the tolerance.

**D2. The false-done rate is broken as wired (blocks the freeze).**
- `orders._false_done` looks for `work` events on the board log. The router never executes `work`, so the board has
  no such event type.
- `team.log` records no releases.
- My probe: four agents each claim, work correctly and release `done` with `check_passed`. Result: `Y = 1.0` and
  **false-done rate 1.0**.
- Rung 0 never issues a release, so nothing caught it (M23 stays green).
- The read-off must join `team.log` work events with the board's releases, and it needs its own test.

**D3. The refusal stop is team-wide, enforced-arm-only, and reset by reads (blocks the freeze).**
- `enforce.Refusals` stops the episode at 3 consecutive or 20 total refusals. The counter is shared by the whole
  team, and an admitted `read` resets it.
- My probe in the `code` arm:
  - Four agents herd on task 0 in round 1 without reads: a1, a2 and a3 are refused, the episode stops, `Y = 0`.
  - The same agents reading first: the episode completes, `Y = 0.25`.
- Herding is the expected model behaviour. `none` and `play` have no refusals.
- The pre-registration forbids behavioural re-runs, so the stop would bias `Y_code` downward on one side only.
- The pre-registration must fix:
  - whether the counter is per agent or per team;
  - whether reads count as admitted actions;
  - whether a stop rule applies at all in EP-1.
- Scripted rung 0 never hits the stop, because adopters always read first.

**D4. The `code` arm's `Y` at rung 0 is a scripted assumption, not router behaviour.**
- `team.turn` sets `follow = adopts or (pid == "A" and enforced)`. Neutral-card agents in `code` are made to follow
  the protocol, so the router claims for nobody.
- With models, whether a neutral agent claims is the measurement. M25 shows what happens to blind agents under the
  lock: refusals and stopped episodes.
- So rung 0 validates the lock's mechanics, not a `Y_code` prediction for EP-1. Do not cite 0.9892 as the EP-1
  code-arm reference.

**D5. EP-1 inputs that `Turn` does not carry.**
- There is no status line (`accepted`, `refused: <reason>`, `no-op`) for the agent's last action.
  `prereg/EP1.md` section 6 requires one in every arm.
- `ctx.shared` is a scripted side channel off the board: the loser rank and the claimed task. It must never reach a
  model.

**D6. Smaller notes.**
- The byte budget is never exercised (M05, M07).
- The neutral card's text is never tested by the driver (M08). See section 2 for whether the unit tests catch it.
- M06 is equivalent only because A refuses the follow-up `work`.

**What EP-1 needs built and gated (call it G1b) before the freeze.** B2, `team_claude.py`, is a new, untested layer
between the model and `router.act`. It must pass its own gate first.

1. **Backend adapter.** `run_episode(backend=...)`, or a sibling loop, sends each turn to `ClaudeClient` and keeps
   `follow` out of the code path entirely.
2. **Prompt format.** System text, then the card or its same-length neutral twin, then the committed snapshot, then
   the status line.
   - Byte-identical across arms except for the card.
   - Hashed into the record.
   - The naming rule is not shown.
3. **Parsing replies into board actions.** One JSON object.
   - Round 1: `claim` or `pass`. Round 2: optional `claim`, `work`, `release`, in that order.
   - The harness sets `agent` itself; a model-written value must not become `identity_spoof` refusals.
   - Anything malformed is a logged no-op and a lost slot.
   - The parser needs mutation tests of its own.
4. **Caps.**
   - A reported input `usage` above 2,000 voids the episode.
   - `max_tokens` 300, temperature 1.0 sent explicitly.
   - A 500-call ledger in which every HTTP attempt counts.
   - The USD cap, the seeded arm order, and the infrastructure-only re-run rule.
5. **The sealed board in a model loop.** Only `router.act` and `end_round`; the model gets the snapshot text only,
   and `ep.shared` is never exposed. One routed read per call, or none, as fixed by D3.
6. **Read-offs fixed and tested:** D1 and D2.
7. **Acceptance for G1b.** The scripted floor (all work task 0) and oracle (4 distinct tasks), run **through the
   model-loop path** with a scripted responder (`fakeclaude`). They must reproduce rung 0's floor and oracle and the
   A table in every arm, after the D3 decision.

**Cheap driver additions, recommended and not made:**
- Assert endpoint CIs of exactly [1, 1] and [0, 0] under common random numbers.
- Put a task-set hash in every record and assert it is equal across arms.
- Add a high-n convergence mode.
- Add expectations for `both`.
- Tighten or replace the collision tolerance.
